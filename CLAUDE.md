# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Blobb** is a story-driven puzzle game in Godot 4.7 (GDScript, GL Compatibility renderer, 1920×1080 canvas). Blobb is based on a child's crayon drawing (`assets/drawing.jpeg`). Two unseen narrators tell the story, and what they say changes the scene live: style, colours, objects, even mechanics. A line can grow branches, shrink a monster, or decide that crates float. Read `docs/story.md` before writing any dialogue. It holds the narrative rules (no family words, tone progression, hidden hospital setting) and the plan for chapters 2–4.

## Commands

Godot runs through flatpak: `godot-flatpak` (wraps `flatpak run org.godotengine.Godot`, with host filesystem access).

```sh
godot-flatpak --headless --path . --import                       # (re)import assets after adding/changing files in assets/
./run.sh                                                         # play (re-imports first, so new class_name scripts are known)
godot-flatpak --path .                                           # play without re-importing (can fail with "Parse error" if a new class_name script was added since the last import)
godot-flatpak --path . -- --scene=res://chapters/ch1/forest.tscn # jump straight into a scene
godot-flatpak --headless --path . --script res://tests/test_sokoban.gd   # puzzle rule tests (prints ALL TESTS PASSED / exit 1 on failure)
godot-flatpak --headless --path . --script res://tests/test_story.gd     # validates every chapters/*/story.txt (run after editing dialogue)
godot-flatpak --headless --path . --script res://tests/test_flow.gd      # ch2 mill-puzzle rules; checks each room's shortest solution (room 3 only with the "backwards" rule)
godot-flatpak --path . -- --scene=res://chapters/ch2/pond.tscn           # chapter 2 (millpond, then chapters/ch2/mill.tscn)
godot-flatpak --headless --path . --script res://tests/test_beams.gd     # ch3 rooftop light-bridge rules; checks each room's shortest solution
godot-flatpak --headless --path . --script res://tests/test_save.gd      # the save point (Continue) and the crash marker; leaves your own save as it was
godot-flatpak --path . -- --scene=res://chapters/ch3/city.tscn           # chapter 3 (town, then roofs.tscn, then chase.tscn)
godot-flatpak --path . -- --scene=res://chapters/ch4/dream.tscn          # chapter 4 (the dreamscape and the short climb)
godot-flatpak --path . -- --scene=res://chapters/ch5/climb.tscn          # chapter 5 (the climb, the summit, the room); --warp=0..4 = section
godot-flatpak --path . -- --scene=res://chapters/ch5/climb_test.tscn     # ch5 mechanics test level (heartbeat ledges, stretch & swing; --autoplay runs a check bot)
godot-flatpak -e --path .                                        # editor
```

**Web export** (single-threaded, no special server headers needed): `godot-flatpak --headless --path . --export-release "Web" build/web/index.html`, then serve `build/web/` (e.g. `python3 -m http.server 8060 --bind 127.0.0.1 -d build/web`). Needs the 4.7.2 web templates in `~/.var/app/org.godotengine.Godot/data/godot/export_templates/4.7.2.stable/`. Preset in `export_presets.cfg` (includes `*.txt`; leaves out tools, tests, docs, raw animation frames, old art). In a browser there are no system fonts (`Fonts.add_fallbacks()` adds `FreeSans-symbols.ttf` for ← → Ⓐ ▾), no Quit button and no crash notice, and textures must stay ≤ 4096 px wide (long animation strips are grids: `tools/grid_strip.py`). `build/` has a `.gdignore`, so stray scripts there never get into Godot's class cache.

Quick testing: press **F1 on the title screen** for the test menu (`scenes/test_menu.gd`: every scene and spots inside it, plus a fast-text switch), or run `./play.sh SCENE [WHERE]` (e.g. `./play.sh roofs 2`, `./play.sh city 39 --fast`; `./play.sh` alone lists the scene names). `Game.start_at(path, at)` is what both use; a warp applies only to the scene it was asked for.

Debug user args (after `--`, parsed in `autoload/game.gd`): `--fast` (narration auto-advances quickly), `--lang=sv`, `--warp=COL` (forest, pond, city and dream: skip the intro and start at a tile column; clearing, mill and roofs: start at room N; chase: start at beat N; climb: section 0–4), `--autoplay` (bots: the forest one runs right and jumps gaps, the pond one swims right at mid-depth, in the mill and on the roofs the rooms solve themselves, and the chase bot jumps and dodges), `--moves=RRUL…|DDR…` (clearing: auto-play box moves, one string per room), `--shots=DIR` (save a screenshot every 2 s), `--quit-after-secs=N`.

Visual check without a window (llvmpipe under xvfb). The screenshot dir must be outside `/tmp`, because the flatpak sandbox has a private `/tmp`. Use `build/` (gitignored):

```sh
xvfb-run -a -s "-screen 0 1920x1080x24" godot-flatpak --path . --resolution 1920x1080 -- \
  --scene=res://chapters/ch1/forest.tscn --fast --autoplay --warp=60 --shots=$PWD/build/shots --quit-after-secs=40
python3 tools/contact_sheet.py build/sheet.png build/shots/*.png
```

An `ERROR: Condition "!is_inside_tree()"` line when using `--scene=` is harmless: the title scene is replaced mid-frame.

**Live checks with gda** ([godot-agent](https://github.com/aigengame/godot-agent)) are the preferred way to verify a change in the running game. You drive it with input, then read its state back as JSON instead of guessing from screenshots. Use `tools/gda.sh`:

```sh
tools/gda.sh start res://chapters/ch3/roofs.tscn   # game on a private Xvfb (:97), windowed so screenshots work
tools/gda.sh input tap --key Space --hold-frames 2 --json      # next line (narration takes key events too)
tools/gda.sh input sequence --events '[{"type":"action","physics_frame":0,"action":"right"},{"type":"action","physics_frame":10,"action":"right","release":true}]' --json
tools/gda.sh input tap --action use --hold-frames 2 --json
tools/gda.sh state                                 # the level's debug_state(): room, lamps, cell, busy, ...
tools/gda.sh shot build/x.png                      # screenshot (the window is 1600x900)
tools/gda.sh game get /root/Roofs/Player --property position --json
tools/gda.sh diag errors --json                    # the game's errors and warnings
tools/gda.sh stop                                  # ALWAYS: stops the game and removes the harness again
```

- **Puzzle playthroughs:** `python3 tools/playtest.py clearing|mill|roofs`, with a session started on that scene. It plays every room of the puzzle in the real game and prints each narration line it sees. Lines starting `!!` are problems: a move that didn't happen, a stuck room, engine errors.
  - Clearing: arrow actions, following the known solutions.
  - Mill: Blobb is placed at each control with `game set`. Short strokes are unreliable under Xvfb because of buoyancy drift. The script presses in the order the solver gives (`debug_plan()`) and waits for the duck to stop between presses.
  - Roofs: real walking and jumping along the strict model's path (`debug_plan(x, y)`). After a fall, the room starts over.

  A full run takes about 3–10 minutes per puzzle.
- Every level declares `const GDA_CALLABLE := ["debug_state"]` and returns a read-only snapshot built with `DebugState` (`scripts/debug_state.gd`). Add the fields a check needs there. The player node is always named `Player`.
- `start` installs `addons/gda_harness/` (gitignored) and a `GdaHarness` autoload line in `project.godot`. `stop` removes both, so never commit while a session is running.
- Setup, once per machine:
  - `uv tool install --python 3.13 "gda[mcp]"`
  - `~/.local/bin/godot-gda`, which is the godot-flatpak line plus `--filesystem=xdg-run/gda`. Without it the game can't reach gda's socket and the harness never connects.
- Each call takes about 0.25 s (a whole session start about 10 s), so this suits checking states and playing puzzles step by step, not real-time action. Use `--fast`/`--autoplay` runs for those. gda's `--scene` can't pass user args (`--warp`, `--fast`). Start at a scene's beginning, or set state with `game set`.
- Headless static checks need no session: `tools/gda.sh script validate res://path.gd --json` (check `valid`), and `tools/gda.sh scene preflight`.

Python asset tools in `tools/` need numpy/scipy/pillow (use a venv; the system Python has only Pillow):
- `key_frames.py` (missing from the repo; the strips it made are committed): keys the black background out of `assets/animations/*/` frames and builds `assets/sprites/blobb_{idle,running,jumping}.png` (321×305 frames). Jump frames after 7 are excluded because they have a baked-in paper background.
- `key_form.py NAME [preview.png]`: keys an animated form from ComfyUI frames on black (`assets/animations/NAME/`) into `assets/sprites/blobb_NAME.png` (grumpy, dash). `BlobbSprite.set_form()` plays the strip when `STRIPS` has one with the form's name, else it shows the drawing.
- `key_superjump.py`: keys the beige-paper jump frames 24–32 into `assets/sprites/blobb_superjump.png` (the stretched, flying Blobb), colour-matched to the other strips.
- `cut_drawing.py`: cuts the figures out of the original drawing into `assets/sprites/drawn_*.png` (see "Blobb's forms" in `docs/story.md`). Pass a path to also write a preview sheet.
- `key_banana.py`: cuts out the banana creature. `make_tiled_bg.py`: mirror-tiles backgrounds into `assets/backgrounds/`.
- `gen_audio.py`: synthesises ch1's SFX and `music_forest.ogg` into `assets/audio/`. `gen_audio_ch2.py` adds ch2's (whistle, drip, bubble, turn, flow, gurgle, `music_pool.ogg`) without touching ch1's. `gen_audio_ch3.py` adds ch3's (kick, hat, crank, lamp_on, coo, flap, `music_city.ogg`). `gen_audio_ch4.py` makes `music_dream.ogg`. `gen_monitor.py` (pure Python) makes the hospital-monitor beep `monitor.wav` used from ch3 on: with no argument it writes candidates and tempo demos to `build/beeps/`, and with a letter it installs that one.
- `solve_flow.py`: BFS solver for the ch2 mill rooms. It mirrors `scripts/flow_room.gd`, so keep the two in sync. Run it after editing `chapters/ch2/flow_rooms.gd`, then update `SHORTEST` in `tests/test_flow.gd`.
- `solve_beams.py`: BFS solver for the ch3 rooftop rooms. It mirrors `scripts/beam_room.gd`, so keep the two in sync. Run it after editing `chapters/ch3/beam_rooms.gd`, then update `SHORTEST` in `tests/test_beams.gd`. Its docstring explains the jump model (how far Blobb can jump, in cells) and the gap rule that keeps it honest.
- `solve_sokoban.py`: BFS solver. Run it after editing any top-down room to prove it's solvable. Update the solutions in `tests/test_sokoban.gd` to match.

## Architecture

- **Autoloads.** `Game` (`autoload/game.gd`) handles language, the input map (registered in code, not in project.godot), `go()` scene transitions with fades, `sfx()`/`music()`, the pause menu, save data (`user://save.cfg`) and debug args. `Narrator` (`autoload/narrator.gd`) is the dialogue layer.
- **Dialogue lives in plain-text scripts.** Each chapter has `chapters/<ch>/story.txt`, which reads like a play: `=== scene ===` blocks, `O:`/`Y:` lines, an optional indented `sv:` line under each (falls back to English), `@effect` lines, `@pause`/`@hold`, and `#` stage directions. The format is documented in that file's header and in `scripts/story_script.gd`. Level code only decides *when* a scene plays (`await story.play("name", self)`). Each `@foo arg` calls `fx_foo(arg)` on the level, so the level scripts hold the `fx_*` methods. `tests/test_story.gd` checks that every effect has an `fx_` method, and every scene the code plays (including the `TRIGGERS` table and `fail_1..4`) exists. When exporting, add `*.txt` to the export filter's non-resource files. `story.play` calls `Narrator.say(lines, blocking)`. Blocking scenes set `Game.control_locked` and wait for the `advance` input; `(ambient)` scenes auto-advance while the player keeps control. Calls queue up; while one is waiting, or Blobb stands at a `StoryGate` waiting for it, the scene playing hurries (`Narrator.HURRY`). The `skip` key (Tab / RB) first shows the whole line being typed, then moves on to the next. Retells never queue behind a scene being told: if `Narrator.busy`, Blobb comes back after a fixed moment without Y's objection (otherwise he'd stay invisible and locked until the queue empties). `Narrator.clear()` (called by `Game.go`) bumps a generation counter so stale or queued lines from the previous scene never play. UI strings live in `Game.UI` and are read with `Game.t(key)`.
- **Quit through `Game.quit()`** (the window's close button does too): it stops all audio and frees the level a moment before the engine shuts down, so nothing is reported leaked at exit. It also removes `user://session.cfg`, the marker written at start: if it's still there next time, the last run crashed, and the title says so beside Continue.
- **Saving (Continue).** `Game.progress_scene`/`progress_at` is the save point: a scene and the number its `--warp` takes (a checkpoint column, a room, a beat, a climb section; -1 = its start), so Continue is `start_at()` and every level's warp code is also its resume code. `go()` saves each new scene from its start; levels save as they go with `Game.checkpoint(at)`: `LevelKit.checkpoint_columns()` (every checkpoint but the first), `_load_room()` in the clearing, mill and roofs, the chase at each roof, the climb per section. `unlock_chapter(n)` moves Continue to chapter n's start (`CHAPTER_STARTS`; n = 6 after the last: nothing to continue). `save()` writes a temporary file and renames it over `user://save.cfg`. Test runs (`Game.testing`: `--scene`/`--warp`/`--autoplay`/`--shots`/`--moves`/`--quit-after-secs`, `--script` tests, gda, the F1 menu) never touch the save point or the crash marker. `tests/test_save.gd` covers it.
- **Player scripts must respect `Game.control_locked`**, which is set by blocking narration, cutscenes and retells.
- **Levels are built in code.** Each `.tscn` is a bare root node with a script. The script builds terrain, collisions, triggers and actors from const data tables (e.g. `GROUND`/`TRIGGERS` in `chapters/ch1/forest.gd`, ASCII rooms in `chapters/ch1/rooms.gd`). Story beats fire from trigger columns via `_beat(name)`.
- **Look changes.** `StyleFX` (`scripts/style_fx.gd` + `shaders/style_fx.gdshader`) is a full-screen post-process CanvasLayer. Each level adds one, with presets `paper`, `crayon`, `dark`, `mono`, `real` and `plain`, plus `tint()`, `white()` and `rewind_pulse()`. Blobb's own colour comes from `BlobbSprite.set_tint()` (`shaders/blobb.gdshader`). His canonical colour is `BlobbSprite.GREEN` at `GREEN_AMOUNT`.
- **CanvasLayer order matters.** World at 0, StyleFX 40, Game fade 55, Narrator 60, pause 90, chapter cards 101. The fade sits *below* the narrator so lines can play over black.
- **Spikes are stubbornness, never a weapon.** A knock makes Blobb prickly for a moment (`BlobbSprite.bristle()`, the grumpy form): the banana in ch1, the fish in ch2 (which dart off, `fish.gd startle()`), and in the ch3 chase (`_bristle()`, spikes drawn in code), which is why a chimney or vent breaks apart. Creatures are never hurt or defeated: the birds only fly off, and the banana comes back in ch2 and ch3.
- **Failure is a "retell".** There is no death. The younger narrator objects ("He didn't fall!"), StyleFX warbles, and the player is reset to the last checkpoint (`_fail()` in forest).
- **Top-down puzzles.** `SokobanGrid` (`scripts/sokoban_grid.gd`) holds the pure rules (undo, water → bridge only when `crates_float`, gate opens when all plates are covered, and the tiny banana `A` in room 3: after each move Blobb makes it takes one step along its row (`banana_step()`), pushing a crate ahead of it or shoving Blobb one cell, else turning; room 3 can only be solved by letting it push crates Blobb can't get behind) and is mirrored by `tools/solve_sokoban.py` (`bstep()` for the banana). Keep the two in sync. `scripts/clearing_board.gd` only renders.
- **Chapter 2.** It's set outdoors: a millpond, then the old mill's channel. `PlayerSwim` (`scripts/player_swim.gd`) has three modes: LAND on the bank, SINK (heavy, hops along the bottom) and SWIM (unlocked by the story). Each frame the level sets `player.flow` for currents, spring lifts and the whirlpool's pull. The mill puzzle is `FlowRoom` (`scripts/flow_room.gd`), which holds the pure rules:
  - Spouts send streams that bend off boards.
  - The duck moves one cell per tick along a stream, or floats up when no stream reaches it.
  - Blobb uses wheels (spouts on/off, and backwards once the story allows it) and levers (flip boards) from behind a fence.
  - It includes a BFS solver.

  Rooms are in `chapters/ch2/flow_rooms.gd`, and `chapters/ch2/mill.gd` only renders and handles input. Retells in every level use `Retell.scribble()/clear()` (`scripts/retell.gd`).
- **Chapter 3.** Outdoors at night, three scenes:
  - `chapters/ch3/city.gd`: the chapter card, then a side-view street (PlayerSide). Lamps come on, Blobb turns gold and back to green, a banana sweeper, the dash form over three canals, a drainpipe up.
  - `chapters/ch3/roofs.gd`: the light-bridge puzzle. `BeamRoom` (`scripts/beam_room.gd`) holds the pure rules plus a BFS solver: cranks turn rooftop lamps, and every beam becomes something to stand on (one-way collision; diagonal beams are 45° ramps, level beams get a short ramp up onto a lamp or roof at their ends; straight-up light is only light). Rooms are in `chapters/ch3/beam_rooms.gd`.
  - `chapters/ch3/chase.gd`: a rooftop lane runner drawn entirely in code (faux-3D Blobb, roofs, chimneys, birds, the hospital), seen from high up straight behind him (`_proj()`: a perspective projection from a camera that never moves sideways, so nothing sways; roof textures are drawn in short strips so they don't slide). One beat clock drives everything: Blobb's distance is the beat, so gaps arrive on the beat. The drum (kick and hat) crossfades into the monitor beep, then speeds up. Only Y speaks there (`LINES`, by beat). A hit is a retell: Y objects and Blobb starts again at the start of the roof he was on, but the chimney, vent or bird he hit stays gone, so nothing stops him twice. A missed gap just means trying that jump again.
- **Chapter 4.** `chapters/ch4/dream.gd`: one short side-view scene. Blobb only walks (no pits, hazards or retells) past drifting props from earlier chapters, while StyleFX drifts between looks and never settles. Only Y speaks (`TRIGGERS`, by column). After "Dad, wake up." `fx_mountain` lifts the mist off a few ledges. Blobb only has ch1's weak hop there; ledges are climbed by pushing into them (`_clamber()`: no arms, those are O's rule in ch5; he heaves his front over the edge, leaning from his feet, strains, and drags the rest of himself up). The first try gets partway and slides back, and Y says "Blobb can't manage without you"; then the monitor beep comes back, its first beep goes through him (Y: "Everything's easier when you're with us."), and from then on he makes it, a little quicker the higher he gets. The beep is very uneven at the foot and only a little uneven at the top, at the top Blobb walks on into a cave mouth (in `mountain.png` at `CAVE_X`; drawn if the painting has none) and the dark closes round him until only he is left, the black chapter 5 starts in. The beep carries on there and evens out as Blobb climbs.
- **Chapter 5.** `chapters/ch5/climb.gd`: the last chapter, a one-screen-wide vertical climb up the ch4 mountain (one-way ledges), all at night. During the opening lines Blobb stands straining (`PlayerSide.rest_anim = "climb"`, the `blobb_climb.png` strip from `assets/animations/climb/`). Heartbeat ledges launch Blobb on each monitor beat (a little uneven at the foot, as ch4 ended; even from the "steady" beat up). After O's rule (`@stretch`) he can stretch to glowing holds and swing (hold E). Story beats by height (`TRIGGERS`); a long fall is a retell. The sky has parallax: the night picture sinks as he climbs, and above it one tall painted starry sky (`assets/gen/ch5/stars_sky.png`, 1920x3000 on black, drawn additively by `shaders/sky_layer.gdshader`) scrolls past: sparse at the bottom, denser upward, the milky way at the top, which fills the screen at the end of the sweep. Without the picture the stars are drawn in code (`STAR_LAYERS`, GPU MultiMeshes via `shaders/sky_stars.gdshader`). At the summit a slow sweep up (`_look_up()`, `LOOK`) past Blobb and the mountain into the sky: more and more stars, faint nebulae, the milky way; a shooting star, then Y wants morning and O a little more rest: the night stays and `@moon` brings out the moon beside the bright star (`assets/gen/ch5/moon.png`, `star_bright.png` on black, drawn additively; without them the narrators' icon shapes). Then the real room at night (the same painted moon and star in the window, `room.png`/`assets/drawing.jpeg` drawing on the wall), then the credits roll over the dimmed room (`CREDITS`, strings `credits_*` in `Game.UI`; holding {advance} or {skip} speeds them up), the lit heart monitor by the bed blips with each beep (`_draw_monitor()`), the drawing on the wall grows to fill the screen (`_zoom_drawing()`) and stays until {advance}, and the end card. `climb_test.tscn` is the plain mechanics sandbox.
- **Prompts.** UI strings name keys with tokens (`{jump}`, `{use}`, `{advance}`, `{skip}`, `{undo}`, `{restart}`, `{arrows}`). `Game.t()` fills them in for the device last used: keyboard keys, or controller buttons (Ⓐ Ⓑ Ⓧ Ⓨ). `Game.input_device_changed` fires when that switches. Puzzle rooms keep a controls legend on screen with `Narrator.legend(key)`, which redraws itself on a device or language change. (An H "hint" key that marked the solver's next step was tried and removed: it didn't work well enough.)
- **The story is never outrun.** Blobb always moves at full speed. In the side-view levels (forest, pond, town, dream), `StoryGate` (`scripts/story_gate.gd`) stops him just short of the next `TRIGGERS` column while a scene is still being told. While he pushes against the stop, the scene hurries (`Narrator.gate_waiting`). In the dream it doesn't hurry (Y's silences matter); instead it sets a slower walk (`walk`) and eases him down as he nears the stop (`slow_over`, `slow_min`), so he strolls instead of stopping.
- **Shared building blocks.** Reuse these instead of writing a level-local copy:
  - `LevelKit` (`scripts/level_kit.gd`, static): `story_columns()`/`checkpoint_columns()` (TRIGGERS and checkpoints by tile column), `column_area()`, `solid()`/`solid_tiles()`, `top_row()` (ground height from span tables), `gradient_rect()` (sky), `follow_camera()` (side-view camera), `drip_loop()`, `hop()`.
  - `Retell.tell()` (`scripts/retell.gd`): the whole retell (rewind, scribble, Y's `fail_1..4`, Blobb pops back) for the side-view levels and the roofs; the level only guards `_retelling`, puts Blobb back and counts.
  - `BlobbBody` (`scripts/blobb_body.gd`): the base of `PlayerSide` and `PlayerSwim` (body, sprite on a squash pivot, `teleport()`, `knockback()`).
  - `PuzzleMarks` (`scripts/puzzle_marks.gd`): the numbered badges and rings of the mill and roof puzzles.
  - `ClimbRig` (`scripts/climb_rig.gd`): ch5's heartbeat ledges, holds and swing, used by both `climb.gd` and `climb_test.gd`.
- **Chapter cards.** `ChapterCard` (`scripts/chapter_card.gd`): `title()` shows "Chapter N" and its name at the start of each chapter (forest, pond, city, dream, climb); `closing()` shows only "The end." after ch5. No chapter has a closing card: each runs straight on into the next chapter's title (`Game.go()` to its first scene). Every chapter starts the same way: controls locked, the title, the same short `breath()`, then the narrators build the scene (`intro`: O sets it, Y changes their half, "Better."). Ch4 is the deliberate exception (Y alone, ambient).
- **Generated art.** Requested from the ComfyUI Claude session (a peer session named `comfyui-*`; find it with ListAgents) (ComfyUI image generation) and saved to `assets/gen/<chapter>/`. Code always checks `ResourceLoader.exists()` and falls back to existing or procedurally drawn art, so the game runs without them. After new files arrive, run the import command.
